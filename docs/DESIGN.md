# BetterSearch 设计文档

> 状态：v0.1 开发前定稿（2026-11-07）。本文记录已确认的产品与架构决策；改动决策时请同步更新本文。

## 1. 定位

BetterSearch 是一个**油猴脚本（userscript）**，增强 Google、Bing、百度的搜索结果页。

- **目标用户**：有一定基础、会装油猴管理器的用户，国内与海外都有。
- **许可证**：GPL-3.0，开源社区项目。规则列表单独建仓库，方便社区提 PR。
- **不做的事（当前阶段）**：浏览器扩展、自建后端、账号体系。

### 1.1 差异点

1. **能处理各种模块的稳定布局，并且高度可自定义**。AC-baidu 的双列模式在 Bing 新模块（「其他用户还搜索过」「深入了解」「资讯」）出现时会错乱，布局死板，自定义能力弱。
2. **防范仿冒官网**：SEO 排名靠前、模仿官网布局、实际提供带毒安装包的站点。
3. **一个脚本覆盖所有功能**，支持 WebDAV 同步，移动端也能用（Via、X 浏览器、iOS Userscripts）。
4. **用自己的 API Key 做 AI 总结和问答**，并且和屏蔽规则联动（自动排除已屏蔽的站点）。

## 2. 版本规划

| 版本 | 内容 |
|---|---|
| **v0.1** | 三个引擎的适配器；去广告；屏蔽规则引擎（关键词 + 域名 + 订阅列表）；防仿冒（启发式规则 + 黑名单）；拦截重定向；自动翻页；结果区布局和主题（2 到 3 个预设）；设置面板 |
| v0.2 | 官网登记表（白名单）；自定义 CSS 和主题分享；紧凑主题；更多 tab（优先「资讯 / 新闻」） |
| v0.3 | AI 功能：网站总结、搜索总结和问答（BYOK）；AI 栏；引擎自带 AI 回答可以移到 AI 栏 |
| 之后 | WebDAV 同步（可提前）、触屏专项优化、浏览器扩展版（可选） |

### 2.1 v0.1 完成标准

- 在 Chrome、Firefox 和 Safari（Userscripts App）的桌面版上，Google、Bing、百度的「全部 / 网页」tab 都能正常工作。
- 页面首次显示时不闪出广告或原始样式：基础 CSS 在 `document-start` 阶段注入。
- 每个适配器都有基于真实页面 HTML 快照的 Vitest 测试。
- 在 Greasy Fork 发布，代码不压缩。

## 4. 架构

```
packages/core        引擎适配器、规则引擎、各功能逻辑、同步合并逻辑（不直接调用 GM_* 或 DOM 全局对象以外的平台 API）
packages/platform-gm 油猴实现：GM_getValue / GM_setValue / GM_xmlhttpRequest
apps/userscript      vite-plugin-monkey 入口，负责组装各部分
fixtures/            各引擎搜索结果页的 HTML 快照
docs/                文档
```

core 层只通过一层很薄的接口访问平台能力（`Storage`、`Http`），这样单元测试里可以换成假的实现。

### 4.1 引擎适配器

每个引擎一个适配器，统一实现以下职责：

- `match(url)`：判断当前页面是不是这个引擎的搜索页，以及当前是哪个 tab（按 URL 参数判断，**不按 tab 的位置判断**）。
- `collectBlocks(root)`：找出所有区块，并给每个区块标注类型。
- `extractResult(block)`：从普通结果中提取标题、显示的域名、真实 URL、摘要、日期。
- `nextPageUrl(doc)`：自动翻页用。
- `isChallenge(doc)`：判断是不是人机验证页（Google `/sorry`、百度 `wappass`）。

区块类型：`organic`（普通结果）、`ad`、`related`、`news`、`video`、`ai-answer`、`paa`（相关问题）、`knowledge`、`widget`（天气、汇率等）、`unknown`。

**`unknown` 类型默认横跨整行显示**，调试模式下会输出日志。这样搜索引擎新增模块时，最坏情况只是不好看，不会把布局搞乱。

**选择器和规则要能远程更新。**适配器的特征规则放在规则仓库里，引擎改版时不用发新版脚本。

### 4.2 页面变化监听

百度和 Google 在一些情况下，换搜索词时只局部更新页面，不重新加载。所以要监听 URL 变化和结果容器的 DOM 变化，检测到新搜索时重新处理整个页面。

## 5. 各引擎调研结论（2026-11）

调研方式：在真实浏览器里，用 workbuddy、北京天气、iphone 17 价格、周杰伦、python list sort、美元汇率、东京塔、今日新闻、chrome 下载、how to make pizza 共 10 个关键词，分别在三个引擎中搜索。

### 5.1 Google

- **tab**：AI 模式（`udm=50`）、全部、图片（`udm=2`）、新闻（`tbm=nws`）、视频（`udm=vids`）、购物（`udm=28`）、短视频（`udm=short_vids`）；「更多」里有地图、图书、网页、航班。**tab 的顺序会随搜索词变化，也会出现新的 tab**（比如「财经」）。
- 结果容器是 `#rso`，但**层级不固定**：有时结果是它的直接子节点（`.MjjYud`），有时外面还包了一层 div。其中还混着大量高度为 0 的空节点。
- 模块：AI 概览（可能在最上面，也可能夹在结果中间，class 是 `.ULSxyf`）、相关问题、视频、短视频、图片、歌曲、专辑、电影、活动、天气、货币换算器、右侧知识面板 `#rhs`、「用户还搜索了」。
- **模块标题会随 IP 所在地变语言**（在日本 IP 下有日文标题），**不能根据标题文字判断区块类型**。
- 拦截重定向：**普通结果的 `href` 是 `/goto?url=CAES…` 这种加密跳转**（2026-11-07 抓取的快照中确认），本地无法直接解码。真实域名要从结果里显示的 URL 文本（`cite`）中读取，处理方式与百度相同（见 6.3）。另外还要去掉 `ping` 属性和 `mousedown` 上报。
- 每条普通结果外层都有 `[data-rpos]` 容器，当前适配器按 `[data-rpos]` → `.MjjYud` → `[data-hveid]` 的顺序查找。
- 广告容器是 `#tads` 和 `#bottomads`。调研时用的日本 IP，没有出现广告，**需要在其他地区再验证**。

### 5.2 Bing（国内版）

- **tab**：网页、图片（`/images/search`）、视频（`/videos/search`）、学术（`/academic/search`）、词典（`/dict/search`）、地图（`/maps`）、航班（`/travel/search`），在测试的关键词下保持不变。国际版的 tab 不一样，需要单独适配。
- 区块的 class 命名很有规律：
  - `#b_results > li.b_algo`：普通结果；变体有 `b_vtl_deeplinks`（带站内链接）、`b_rc_gb_template`（富卡片）
  - `li.b_ans`：模块。其中 `b_top` 是直接答案，`b_mop` / `b_vidAns` 是轮播，标题是问句的是相关问题
  - `#b_topw`、`#b_pole`：结果列表上方的大区块
  - `#b_context`：右侧栏
  - `.b_pag`：分页
- 品牌广告会出现在 `#b_results` 外面（比如搜 workbuddy 时）。**这次的广告检测选择器没有覆盖到 Bing 的广告，需要补充。**
- 拦截重定向：`bing.com/ck/a?...&u=a1<base64url>` 可以在本地解码。

### 5.3 百度

- **tab**：网页、图片、资讯、视频、笔记、地图、贴吧、文库、更多，另有「搜索工具」。tab 的链接带 `dyTabStr` 参数，说明是动态生成的。
- 结果容器 `#content_left` 的子节点**带有 `tpl` 属性，可以用来可靠地判断类型**：
  - 普通结果：`www_index`、`www_struct`
  - AI 内容：`wenda_generate`、`ai_agent_distribute`、`new_baikan_index`，另有 `ai-entry` 入口
  - 生活服务和数据：`weather_forecast_new_san`、`jr_exrate_san`、`jr_quote`、`jr_stock_comment_san`、`sp_purc_pc`
  - 内容聚合：`sg_kg_entity_san`、`bk_polysemy`、`tieba_general`、`tieba_star`、`image_grid_san`、`short_video`、`yl_vd_main_san`、`yl_vd_series_san`、`rel_base_realtime`、`recommend_list`
  - 软件下载：`pc-soft-accurate`
- **广告没有 `tpl` 属性，class 是随机字符串**（比如 `u2a6nht`），要用特征组合来识别：没有 `tpl`、链接指向 `baidu.php`、区块里带有「广告」字样。广告密度很高（搜「iphone 17 价格」时前 7 个区块里有 3 个），而且在「下载」类搜索里，**广告标题经常伪装成下载站**。
- 没有 `tpl` 的非广告区块：`c-group-wrapper`（人物关系、分步教程）、`search-source-wrap`。
- 拦截重定向：区块上的 **`mu` 属性就是真实地址**。
- 右侧栏 `#content_right`：相关搜索（`recommend_list_san`）、热搜榜（`right_toplist1`）。

### 5.4 仿冒站实例

在 Bing 搜 workbuddy 时，前 10 条里有 3 条标题自称「官网」，域名是 `workbuddy-dt.com.cn`、`workbuddy-sy.com.cn`、`workbuddy-sc.com.cn`（这些站点本身是否恶意没有核实）。百度搜「东京塔」时，前 10 条里有 4 条是「免费观看完整版」类的影视站。这两种情况都作为启发式规则的测试用例。

## 6. 功能设计

### 6.1 屏蔽规则

- 规则作用于**搜索结果**：标题、摘要或 URL 命中规则时，结果会被**隐藏**或**折叠**成一行「已屏蔽 N 条，点击显示」。
- **规则语法兼容 uBlacklist**，订阅列表也用同样的格式，在此基础上扩展关键词规则和处理方式（隐藏、折叠、警告）。
- 日常操作：每条结果上都有「屏蔽此站」按钮，屏蔽后弹出带撤销按钮的提示。只有高级模式才需要手写规则。
- 订阅列表每 24 小时检查一次更新。来源依次尝试 jsDelivr 和 Gitee 镜像，失败就换下一个。

### 6.2 防仿冒官网（分级处理）

| 来源 | 处理方式 | 版本 |
|---|---|---|
| 仿冒站黑名单（社区维护的订阅列表） | 屏蔽或折叠 | v0.1 |
| 启发式规则：在品牌名后面加 `-xx`、`-cn`、`-download`、`xiazai` 之类的后缀；标题自称「官网」「官方下载」，但域名对不上；百度结果中显示的域名和真实域名不一致 | **只显示 ⚠️ 提示，不自动屏蔽** | v0.1 |
| 官网登记表（「品牌 → 官方域名」，社区维护） | 显示 ✅「官方」标记，可以选择置顶 | v0.2 |

- 每条结果都有「举报仿冒」按钮，点击后跳转到 GitHub issue，域名和搜索词已经预先填好。
- 名单使用中性的名称，每条记录附上依据，并提供申诉通道（issue 模板）。名单默认不开启，由用户自己订阅。

### 6.3 拦截重定向

- Google：去掉 `ping` 属性，拦截 `mousedown` 上报。链接是 `/goto?url=` 加密跳转，处理方式与百度相同：先用显示的 URL 做防仿冒判断，点击时再解析。
- Bing：在本地解码 `ck/a` 链接里的 `u` 参数。
- 百度：优先读取 `mu` 或 `data-tools` 属性。都没有时，先用页面上显示的域名做防仿冒判断，**用户点击时再通过 `GM_xmlhttpRequest` 解析真实地址**，结果缓存 24 小时。如果真实域名和显示的不一致，升级为 ⚠️。
- 默认去掉链接里的跟踪参数（`utm_*`、`spm`、`from` 等），保留一个白名单。
- 在新标签页打开做成开关，默认保持引擎原来的行为。

### 6.4 自动翻页

- 滚动到接近底部时自动加载。**加载 5 页后改为显示「加载下一页」按钮**，这个数字可以在设置里改。
- 在后台同源请求下一页的 HTML，用同一个适配器解析，同样经过去广告、屏蔽和防仿冒处理。
- **第 2 页以后只追加普通结果**，按 URL 去重。
- 遇到人机验证页就停止，提示用户手动打开下一页，并附上链接。每次请求至少间隔 1 秒。
- 页与页之间显示「第 N 页」分隔线，默认不修改地址栏。

### 6.5 布局与主题

- 页面分成三个区域：**搜索结果区**、**侧栏**、**AI 栏**，各自独立设计和配置。先做搜索结果区。
- 只有普通结果进入网格。其他模块可以分别设置为**横跨整行、移到侧栏、折叠或隐藏**。
- **结果区默认参数：2 列、卡片样式、紧凑密度、跟随系统深浅色。**列数会根据屏幕宽度自动减少，在手机上变成单列。
- 多列时**按行排列**，这样阅读顺序和搜索排名一致。网格设置 `align-items: start`，标题最多 2 行，摘要最多 2 到 3 行。
- **引擎自带的 AI 回答默认折叠成一行**，点击后展开。
- 主题由一组 CSS 变量（`--bs-*`）加上可选的额外 CSS 组成，可以导出成 JSON 分享。所有引擎共用同一套变量，每个引擎也可以单独覆盖。
- 视觉原则：**域名就是判断可信度的依据**。域名用等宽字体显示，主域名加粗，子域名和路径用浅色，仿冒域名里和官网不同的部分高亮。
- 字体：IBM Plex Sans 和 Plex Mono，中文回退到苹方或思源黑体。
- 设计稿：claude.ai artifact `8eAGvTe2JHhXtqJHKeQsqS`（「第二轮：搜索结果区」页面）。

### 6.6 设置界面

- 入口：搜索框旁边的齿轮按钮为主，油猴菜单作为备用，另有快捷键 `Alt+,`。
- 形式：放在 Shadow DOM 里的**右侧抽屉**，**改动实时预览**；手机上改为从底部弹出的面板。
- 标签页：外观、屏蔽、安全、同步、高级。
- 界面语言：中文和英文，根据浏览器语言自动切换。

### 6.7 同步（WebDAV）

- 只同步用户自己的配置：设置、个人规则、订阅地址。订阅列表的具体内容各端自己下载。
- 通过 `GM_xmlhttpRequest` 发请求，需要在脚本头部声明 `@connect *`。提示用户使用应用专用密码。
- **按字段合并**：设置项各自比较修改时间，以最后修改的为准；规则按 `id` 合并，删除时保留 tombstone 标记。云端保留最近 N 个历史版本作为备份。
- 同步时机：打开搜索页时同步，两次至少间隔 10 分钟；修改配置后延迟几秒上传；另有手动同步按钮。
- 配置里带 schema 版本号，格式变化时自动迁移。

### 6.8 AI（v0.3）

- BYOK，统一用 OpenAI 兼容接口。预设：DeepSeek、通义千问、Kimi、智谱、OpenAI、Claude、Gemini，也可以填自定义的 Base URL（比如本地 Ollama）。
- 数据从用户浏览器直接发给模型厂商，不经过 BetterSearch。

## 7. 开发顺序

1. **第 0 步**：搭好项目骨架，在 Google 搜索页上给每条普通结果加上边框，跑通开发流程。
2. **第 1 步**：完成 Google 适配器，做去广告、域名屏蔽和最简单的设置面板。
3. **第 2 步**：完成 Bing 和百度的适配器，根据实际情况调整适配器接口。
4. **第 3 步**：拦截重定向、自动翻页、订阅列表、防仿冒、主题，完成 v0.1。
